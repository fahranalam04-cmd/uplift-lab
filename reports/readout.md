> Generated by `uplift-lab report` from `reports/*.json`; every number below is computed by code in this repo. Scope: CPU only (i7-11800H, 4 threads).

## TL;DR

* Display advertising raised visits by **0.744 pp** (95% CI [0.719, 0.768], +18.4% relative; doubly-robust estimate) across 13,979,592 users. The naive difference in means (1.034 pp) overstates it, because the file pools several tests whose treatment shares differ with users' baseline visit propensity.
* SRM passes, but the features predict treatment (AUC 0.511, CI excludes 0.5), and adjustment moves the estimate by far more than chance. Without a balance check this would have been missed.
* Cross-fitted CUPAC + linear adjustment narrows the visit CI by 17.0%, the same precision as 31.1% more users.
* Simulations on real outcomes: A/A FPR 5.09% over 10,000 sims; peeking 1000 times inflates FPR to 65.6%, while the mSPRT holds it at 2.34%.
* Targeting: the top 30% by Transformed outcome captures 86.3% of incremental visits on the test split (random: 30%).

## 1. Design and guardrails

* **Population:** 13,979,592 users (11,882,655 treated, 2,096,937 control). Visit rate 4.70%, conversion rate 0.292%. Control users can never be exposed (control_exposed = 0), so this is one-sided non-compliance.
* **SRM:** observed treatment share 0.8500001 vs the documented 0.85; chi-square = 1.82e-06, p = 0.999 -> **no SRM**. At this n the check would alarm (p < 0.001) for a share deviation as small as 0.00031. Caveat: the public file was sub-sampled by Criteo, and the share being this close to 0.85 suggests the ratio was fixed when the file was built, so passing SRM is weak evidence here.
* **Covariate balance:** every |SMD| is below the 0.1 rule of thumb (max 0.049), but with SE 0.00075 under randomization the largest is 65 SEs from zero. A gradient-boosted classifier predicts treatment from the 12 pre-treatment features with AUC 0.5106 (95% CI 0.5090-0.5122, n = 1,001,835); the cross-fitted LightGBM propensity on all users gives AUC 0.5095, with e(x) between 0.782 and 0.960 (good overlap, no clipping needed).
* **Why:** in the original CSV order the file consists of 13 contiguous single-arm blocks with visit rates from 0.00% to 8.58%. That fits the dataset card ('assembling data resulting from several incrementality tests'). Tests with different treatment ratios and base rates were pooled, so assignment is random *within* a test but not across the pooled file. Test ids are not released; the features only partly encode them.

**Reading this table:**

1. **Precision.** CUPAC + 12 features shrinks the visit CI by 17.0%, the same precision as an unadjusted test on 1.45x as many users (a 31.1% sample-size saving at equal precision). For conversion the gain is smaller: 6.4% narrower, 12.5% sample-size equivalent. Rare outcomes are hard to predict (out-of-fold R^2 0.127 vs 0.335 for visit).
2. **Accuracy.** Under clean randomization, adjustment moves the point estimate by well under one SE. Here it moves visit by 28% (Hausman z = 40), consistent with the imbalance above. The raw ITT overstates the lift because the high-propensity-to-visit decile is 86.1% treated vs 84.6% in the lowest decile.
3. **Estimate of record:** AIPW, doubly robust (cross-fitted) = 0.744 pp [0.719, 0.768] on visit (+18.4% relative) and 0.0999 pp on conversion (+48.8%). The adjusted estimators span 0.666 pp to 0.773 pp, wider than their CIs. That spread is model dependence: the features are only a proxy for the unreleased test id, so some residual confounding is possible. The direction (raw overstates) is robust; the exact size of the overstatement is not.

## 4. Does the methodology hold up? Simulation studies

## 6. Recommendations

1. Report the doubly-robust ITT, not the raw difference, for this pooled file; ask the data owner for the test id so the analysis can be stratified exactly.
2. Run the balance / treatment-predictability check on every experiment. It is cheap, and it catches problems that SRM cannot see.
3. Adopt CUPAC as the default estimator for visit-type metrics. At equal precision it cuts the required sample by about the R^2 of the prediction. Gains on rare conversions are smaller.
4. If stakeholders will monitor results daily, use always-valid p-values (mSPRT). The fixed-horizon test is only valid if it is read once.
